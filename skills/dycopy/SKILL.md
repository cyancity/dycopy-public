# dycopy

先定位包含 `dycopy.py` 的源码目录，读仓库 [README.md](../../README.md) 和当前命令的 `--help`。随仓库分发时，源码根目录位于技能目录上两级；单独安装技能后需另行定位源码。不要假定用户目录、虚拟环境或素材库的位置。

复用已有解释器、浏览器和模型缓存。依赖缺失时指出缺项，按当前授权处理安装；不要自行切换付费服务。浏览器启动、转写静默或输出异常时，读 [故障定位](references/troubleshooting.md)。

## 选择入口

- 单条作品，下载媒体并提取文案和元数据。用户要求逐字稿时再启用 ASR；需要逐字稿和视频时同时传 `--asr` 与 `--download`。
- 多条作品，按作品 ID 去重后逐条处理。未要求转写时不启动 ASR。
- 一个或多个主页，按 `sec_uid` 去重，核对列表完整性后归档图文、视频和 Live Photo。默认只下载媒体。

在源码目录使用虚拟环境解释器。例如 macOS / Linux：

```bash
.venv/bin/python -u dycopy.py "作品链接" --asr faster-whisper --download --srt --out result
.venv/bin/python -u dycopy.py links.txt --download --media-only --out downloads
.venv/bin/python -u sync_role_library.py --profiles profiles.txt
```

Windows 将解释器换为 `.\.venv\Scripts\python.exe`。示例输入需替换为用户提供的作品或清单。不同链接指向相同作品时只处理一次。

## 列表完整性

匿名列表可能少于页面显示的作品数。记录页面作品数、取回数和分页是否明确结束，不把接口返回成功当成全量。

需要登录态时复用用户已有且明确授权使用的浏览器页面，可通过仓库提供的 Chrome 扩展读取列表，再交给本机串行队列。没有登录态且数量不一致时，报告差额，不宣称全量。不要导出、共享或提交 Cookie、完整作品响应和签名媒体地址。

主页清单每行一个主页 URL 或 `sec_uid`。补录清单通过 `--works` 传入，每行一个作品链接；需带作者 `secUid=` 或 `/user/<sec_uid>`，以便归到正确作者。

## 去重、重试与输出

- 同步脚本与服务默认共用源码根目录的 `.local/dycopy/processed_aweme_ids.json`，媒体输出到 `downloads/`。明确指定路径时以参数为准。
- 不同时启动两个写入同一状态库的进程。并行实例使用独立状态库和输出目录。
- 用 `aweme_id` 判断是否处理过，成功下载后登记。用户删除媒体后，已有 ID 仍跳过。失败项保留供重试，不先记成功。
- 图文保存原图，Live Photo 动态片段作为补充。动态片段失败不阻塞静态图归档；无可用媒体时报告失败，不生成伪视频。
- 下载严格串行。按作品 ID 定点重试失败项，避免重跑完整主页。

汇总列表作品数、新下载数、按 ID 跳过数、失败数及与页面数量的差额。不把退出码或旧文件当成本次成功证据。

8788 是扩展的本机服务端口，CLI 不依赖它。需要服务时先核对端口占用和健康状态，不误停其他程序。扩展每日增量检查需浏览器、登录态和本机服务同时可用。

## 转写与分析

已有完整媒体、逐字稿和 SRT 时先复用。faster-whisper 和 SenseVoice 在本机推理，首次使用会下载模型。SiliconFlow 会上传音频，需要当前任务授权和用户自己的 Key；优先通过 `SILICONFLOW_API_KEY` 环境变量读取，不写进文件或日志。

ASR 数分钟没有输出不等于卡死。检查阶段、进程计算活动和产物变化，保留实时日志，没有证据时不编造进度。分析文案优先使用逐字稿和少量关键帧，不自动扩大为全片 OCR。
